## 1. Сведения о модели (Model details)

## 2. Назначение (Intended use)

Модель оценивает вероятности трёх статусов наблюдения по табличным признакам и выбирает наиболее вероятный класс. Пользователи — участники учебного проекта, преподаватели и исследователи. Назначение — воспроизводимые эксперименты, сравнение базовых решений и демонстрация пакетного прогнозирования.

Это не модель времени до события и не прогноз смерти в течение фиксированного срока. C означает цензурированное наблюдение без трансплантации; CL — цензурирование вследствие трансплантации; D — смерть. Метка C не означает гарантированного выздоровления.

Применение для постановки диагноза, назначения лечения и автоматического принятия решений о пациентах не предусмотрено. Заявления об улучшении выживаемости этой моделью не подтверждены оценкой проекта.

## 3. Вход, выход и факторы качества (Factors)

Вход — CSV, одна строка на наблюдение, 18 обязательных столбцов признаков.

| Тип | Столбцы |
| --- | --- |
| Числовые | `N_Days`, `Age`, `Bilirubin`, `Cholesterol`, `Albumin`, `Copper`, `Alk_Phos`, `SGOT`, `Tryglicerides`, `Platelets`, `Prothrombin`, `Stage` |
| Категориальные | `Drug`, `Sex`, `Ascites`, `Hepatomegaly`, `Spiders`, `Edema` |
| Цель при обучении | `Status`, без пропусков, все три класса C, CL, D |
| Необязательный идентификатор | `id`; переносится в результат, но не используется моделью |

Единицы измерения должны совпадать с обучающим CSV. Код не проверяет единицы и клиническую правдоподобность значений. Название `Tryglicerides` сохраняется в точности как в исходной схеме. `Stage` обрабатывается как числовой признак.

Предобработка: числовые пропуски заменяются медианой, затем применяется StandardScaler; категориальные — наиболее частым значением, затем OneHotEncoder. Неизвестные категории игнорируются кодировщиком, что позволяет выполнить прогноз, но не гарантирует его качество. Все преобразования обучаются внутри Pipeline только на обучающей части соответствующего разбиения.

Выход — CSV со столбцами `Status`, `prob_C`, `prob_CL`, `prob_D` и `id`, если он присутствовал во входе. `Status` выбирается по максимальной вероятности. При предсказании истинный `Status` не требуется и в признаки не включается.

На качество могут влиять доли классов, пропуски, новые категории, единицы измерения, пол, возраст, стадия и длительность наблюдения. Отдельные оценки по демографическим и клиническим подгруппам пока отсутствуют.

## 4. Метрики (Metrics)

Основная метрика — многоклассовый Log Loss: оценивает вероятности и штрафует уверенные ошибки; меньше — лучше. Дополнительно рассчитываются accuracy и F1 macro. Accuracy показывает общую долю правильных ответов; F1 macro придаёт одинаковый вес каждому классу и помогает замечать проблемы при дисбалансе. Специальная калибровка вероятностей не выполнялась.

## 5. Данные обучения (Training data)

Используется `data/raw_data.csv`, 7905 строк. README связывает проект с [Kaggle Playground Series S3E26](https://www.kaggle.com/competitions/playground-series-s3e26). Данные проекта не следует считать доказанной репрезентативной выборкой реальных пациентов для клинического внедрения; происхождение каждой записи и переносимость отдельно не проверялись.

SHA-256 CSV: `cdd70050ef50682c8ee5f17779d9076e5ac03858f89b10f44c37a82eb1e2e952`.

Стратифицированное разбиение: 6324 строки для обучения, 1581 для теста; test_size=0.2, random_state=8. На обучающей части выполняется StratifiedKFold: 5 фолдов, shuffle=True. Это фиксированный baseline без нового подбора гиперпараметров и выбора победителя среди алгоритмов.

## 6. Данные оценки (Evaluation data)

Отложенные 20% получены из того же CSV. Pipeline обучается на 80%, после чего оценивается на тесте. Внешняя, временная и межклиническая валидация не выполнены. Независимость на уровне реальных пациентов и отсутствие семантической утечки признаков отдельно не доказаны.

Запуск предсказаний на всём `raw_data.csv` является проверкой работоспособности интерфейса, а не независимой проверкой качества: часть этих строк участвовала в обучении.

## 8. Этические аспекты (Ethical considerations)

Ошибочный прогноз может создать ложную уверенность или завысить воспринимаемый риск. Вероятности не являются медицинским заключением. Перед возможным применением вне учебной среды нужны независимая валидация, проверка качества для разных групп и экспертная оценка. При работе с реальными данными требуется контролируемый доступ; персональные сведения пациентов нельзя публиковать в репозитории.

## 9. Ограничения и рекомендации (Caveats and recommendations)

- `N_Days` содержит длительность наблюдения и может быть неизвестен в предполагаемый момент раннего прогноза. Его использование создаёт риск временной утечки. До прикладного использования необходимо определить момент прогноза, доступные на этот момент признаки и заново оценить модель без недоступных признаков.
- Цензурирование и неодинаковая длительность наблюдения ограничивают трактовку классов как клинических исходов.
- Код отклоняет пустой набор, отсутствие нужных столбцов, некорректные числа и бесконечности, но не реализует полную проверку диапазонов, дубликатов, долей пропусков и дрейфа.
- Вероятности требуют отдельной проверки калибровки; качество на новых источниках неизвестно.
- Повторный подбор решений по одному тесту приводит к переобучению на оценку. Для следующих выпусков нужен отдельный протокол валидации.
- Загружать `joblib` следует только из доверенного источника. Окружение воспроизводится по `poetry.lock`.

## 10. Воспроизведение и связанные документы

Из корня репозитория:

```bash
poetry install --with dev
poetry run pytest -q
poetry run cirrhosis-train --config configs/train.toml
poetry run cirrhosis-predict --input data/raw_data.csv --output artifacts/predictions.csv
```

Обучение создаёт `model.joblib` и `metrics.json` в `artifacts/`; повторный запуск в ту же папку перезаписывает эти файлы. Процесс применения описан в [Model_BPMN.md](Model_BPMN.md), проектируемое переобучение — в [Model_retrain_BPMN.md](Model_retrain_BPMN.md).
